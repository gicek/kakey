# Kakey Android Technical Notes

> Implementation details of `Android/app`, shared by Android phones and tablets. For cross-platform contracts see [TECHNICAL](../../docs/TECHNICAL.md) and [SECURITY](../../docs/SECURITY.md); for interaction see [DESIGN](../../docs/DESIGN.md); for the shared core see [Core TECHNICAL](../../Core/docs/TECHNICAL.md).

## Project

- Gradle Kotlin DSL. The version catalog `gradle/libs.versions.toml` manages every dependency and plugin, and the wrapper is checked in. AGP 9 has built-in Kotlin support, so the Compose compiler plugin is the only extra plugin.
- `applicationId` `com.gicek.kakey`, `namespace` `com.gicek.kakey.android`. minSdk 33, targetSdk 36, compileSdk 37 (required by the AAR metadata of AndroidX adaptive and activity). Only `arm64-v8a` is built. `versionName` and `versionCode` are read from `Apple/project.yml`.
- Gradle output goes to `Build/Android/Gradle/`: the root `build.gradle.kts` sets `layout.buildDirectory`, and the Makefile points `.gradle` and the Kotlin session directory there too. `make android` copies the debug APK to `Build/Android/Debug/Kakey-<version>.apk`; `make android-release` copies the release APK, AAB, and R8 mapping to `Build/Android/Release/`. ktlint, detekt, Lint, and unit test reports are in `Build/Android/Gradle/app/reports/`.
- The shared core is wired in through the variant API (`androidComponents.onVariants`): `libkakey_ffi.so` from `Build/Core/android/jniLibs/` and the UniFFI bindings (package `com.gicek.kakey.core`) from `Build/Core/android/kotlin/`. The bindings call the core through JNA. The app uses the JNA AAR; JVM unit tests use the JAR and load the host build `Build/Core/android/host/libkakey_ffi.dylib` through `jna.library.path`.
- String resources aren't checked in. The `generateKakeyResources` task runs `scripts/android_strings.py` to generate `strings.xml` in three languages and copies the code font to `res/font/atkinson_hyperlegible_mono.ttf`. AGP's `generateLocaleConfig` generates the app language list.
- Cloud storage callbacks: `oauthSchemes()` in `app/build.gradle.kts` injects the intent filter schemes of `OAuthRedirectActivity` from `cloud-keys.toml` (placeholder schemes when not configured).
- Permissions: the source manifest declares `CAMERA` and `INTERNET`, and `<queries>` declares `com.dropbox.android`. `ACCESS_NETWORK_STATE`, pulled in by dependencies, is removed with `tools:node="remove"` (and CameraX's `camera-video` is excluded). Each variant's `check<Variant>ManifestPermissions` task checks the merged manifest before building the APK or AAB and before unit tests, and fails on any network permission other than `INTERNET`. `allowBackup="false"`, and `data_extraction_rules` excludes all data. `network_security_config` trusts only system certificates and allows cleartext (for HTTP backup locations the user has confirmed).
- Only dependencies actually used are declared. `FragmentActivity` comes from an explicit `androidx.fragment`. There is no `@Preview` and no `ui-tooling` (it adds an exported activity to the Debug manifest). No ViewModel is used.
- Static checks: ktlint (`.editorconfig`, line length 140); detekt (`detekt.yml`; every catch at a platform boundary rethrows `CancellationException` first, so `TooGenericExceptionCaught` and `SwallowedException` are off); Android Lint (`warningsAsErrors`; `app/lint.xml` turns off checks that don't apply, and `CustomX509TrustManager` is suppressed only for the pinning trust manager). They run in the same Gradle invocation as the JVM unit tests.
- Release: `make android-release` runs `assembleRelease` + `bundleRelease`. The keystore reaches `signingConfigs.release` through Gradle properties; without one, the config does `initWith(debug)` and prints a notice. The R8 keep rules (`proguard-rules.pro`: JNA, `com.gicek.kakey.core.**`) have been verified on a device with a Release build.
- Icons: `scripts/export-app-icon.py` exports the adaptive icon foreground and monochrome layer from the transparent logo; the background is a gradient matching the logo. The splash screen uses the foreground directly.
- The Debug-only `src/debug/.../DemoVault.kt` (an empty implementation in `src/release`): `adb shell am start … --ez kakey.demo true` uses a demo vault in the cache directory with an in-memory key, unlocks automatically, and doesn't set `FLAG_SECURE`. `kakey.demo.locked`, `kakey.demo.empty`, and `kakey.demo.screen <screen>` stop on a given screen; `--ei kakey.demo.count <N>` pads the accounts up to N.

## State and Threading

- `VaultStore` lives in `KakeyApplication`, not in a ViewModel, so the unlocked state and any sync in progress survive a language change (the system per-app language recreates the activity) and rotation. The UI subscribes with `collectAsStateWithLifecycle`. State holds only `UiText` (resource ID + arguments), resolved in the current language at display time.
- At launch `VaultStore` is in `Phase.LOADING` and reads settings, backup history, the vault, and the biometric key material in a coroutine; `setKeepOnScreenCondition` keeps the splash screen up until it is ready.
- All file IO runs serially on the injected `files` dispatcher (`Dispatchers.IO.limitedParallelism(1)`). `io` runs only work that can go in parallel (Argon2id for import and export, Keystore, the sync folder, backup history).
- Account changes update memory first. `AccountEditor.persist()` takes a snapshot on the main thread (file generation, a copy of the key, contents), queues the write, and queues a sync once it succeeds. While dragging to reorder, only memory changes; `commitOrder` saves once on release.
- Operations that replace the whole file (create, change password, fetch a backup, restore), together with the key swap and re-storing the biometric material, run in `withContext(files + NonCancellable)`, so a UI cancel can't cut them short. Replacing the file bumps the generation, and saves queued earlier give up when they see it changed.
- Settings read-modify-write completes atomically with `MutableStateFlow.updateAndGet` before writing DataStore. Locking only zeroes the in-memory key; queued saves finish with their own key copies. `CancellationException` is always rethrown.
- **Auto-lock**: unlocking records `lastActivityElapsedMillis` from the monotonic clock. `MainActivity.onUserInteraction()` refreshes it through `VaultStore.noteUserActivity()` (Compose dialogs, bottom sheets, and the IME are separate windows, so the first touch back in the main window catches up). `UnlockController.scheduleAutoLock()` `delay`s until the deadline and checks again. Returning to the foreground (`onStart`) and changing the setting also recheck.
- **Failed attempts**: the wait is stored as "total seconds + start on the monotonic clock" rather than a deadline, so changing the system time can't skip it. After a reboot, a start in the future is reset to now and the full wait starts again. Wrong current passwords when changing the password share the counter with unlocking.
- After importing a backup, `VaultRepository.adoptingPinned` calls the core's `coreAdoptPinned`, so pinned Authenticator entries join the "Favorites" category, named in the current language.

## Platform Capabilities

- **Biometrics**: `KeystoreVaultKeyStore` wraps the key with RSA-OAEP. Keystore OAEP decryption supports only MGF1-SHA1, so both sides explicitly use `OAEPParameterSpec("SHA-256", "MGF1", SHA1)`, and wrapping rebuilds the public key Keystore returns from its encoding before handing it to a software Cipher. Keystore lookups and key file reads run on `Dispatchers.IO`; only `BiometricPrompt` runs on the main thread. `Biometrics.kind()` picks the UI wording from `FEATURE_FINGERPRINT` / `FEATURE_FACE` (the strong biometric check doesn't say which kind).
- **Reset**: after confirmation, `Biometrics.verifyOwner` asks for biometrics or the screen lock credential. When the device has neither, the confirmation dialog is the only check.
- **Cloud storage**: `SyncLocation` (`Folder` / `Cloud`) is stored in `Preferences.syncLocation`. `CloudSyncBackend` drives core operations through `CloudOperationRunner`. `OkHttpExecutor` doesn't follow redirects, store cookies, cache, or retry, and reads at most the limit + 1 byte of a response body; pinned connections use `PinningTrustManager` (which first delegates to the system default trust manager). `KeystoreCloudConnectionStore` keeps the connection blob (Keystore AES-256-GCM, no user authentication required). A rejected conditional write throws `RemoteChanged`, and `SyncCoordinator` decides once more.
- **OAuth**: `CustomTabAuthenticator` opens the sign-in page with an `ACTION_VIEW` carrying `customtabs.extra.SESSION` (no dependency on `androidx.browser`). `OAuthRedirectActivity` (transparent, `noHistory`) hands `OAuthCallbacks` only callbacks the core confirms belong to the current sign-in, then returns to `MainActivity` with `CLEAR_TOP | SINGLE_TOP`. Dropbox prefers the official app: `OfficialDropboxAppAuthenticator` checks the signing certificate of `com.dropbox.android` and sends `AUTHENTICATE_V2` with the official SDK's extras; the result comes back to `OAuthRedirectActivity` and goes through `DropboxAppCallbacks`. When the app isn't available, it returns null and sign-in uses a Custom Tab.
- **External file limit**: imported files and the vault in a sync folder are read up to `FileLimits.MAX_EXTERNAL_FILE_BYTES` (16 MiB). Imports are read in the background.

## UI Implementation

- Navigation: Navigation 3's `NavDisplay`, with the back stack saved through `rememberSaveable`. Animations are defined in `ui/theme/Transitions.kt` and chosen in `ui/main/NavTransitions.kt`: forward navigation switches instantly and the new page animates itself in; the back button uses a shared X axis; predictive back gestures take 200 ms. The direction comes from the order of the two pages in the back stack (`NavTransitionsTest`), not from the spec NavDisplay picks (a back gesture during an unfinished forward animation makes Navigation 3 evaluate the forward spec). The manifest declares `enableOnBackInvokedCallback`.
- Layout breakpoints (`WindowSizeClass`): below 600dp, a single column; at 600dp and up, a card grid (`GridCells.Adaptive(300.dp)`); at 840dp and up, also a permanent sidebar.
- **Drag to reorder** (`ReorderController`): reads the `layoutInfo` of the lazy list or grid through a `Layout` interface and calls `VaultStore.move` (memory only) based on which item the dragged item's center is over. The dragged item doesn't move inside the list. Instead, `ReorderOverlay` puts a floating copy in the host Box that follows the finger, the item's slot in the list stays as a faded placeholder, and other items slide with a critically damped `animateItem` (otherwise the frame of the swap jumps a row and springs back). After each swap, `requestScrollToItem` pins the scroll position by index (lazy containers anchor to the first visible item's key by default, so dragging the first item would jump all the way to the end). Within a 56dp edge zone, `scrollBy` runs every frame via `withFrameNanos`, with speed growing linearly with depth up to 1200dp/s at the edge. The pure math is in `EdgeAutoScroll` and `ReorderController.targetOf`, covered by JVM tests with a fake layout and a manually advanced frame clock.
- **Long-press menu**: not `DropdownMenu` (when it doesn't fit above or below, it centers on the anchor, far from the finger), but a `Popup` with a custom `PopupPositionProvider` (`TouchMenuPosition`). The gesture lives in `AccountItem.accountGestures`: the menu opens after the timeout, and moving past the touch slop afterward closes the menu and starts a drag (the menu is a Popup in another window, so the system still delivers the remaining events to the window that got the press). "Add to" is a `ModalBottomSheet` in `ui/main/AddToSheet.kt`; checked items are staged in a `mutableStateMapOf`, and "Save" calls `setAccountCategories` once (a single `persist()`).
- **Visuals**: in stable Material 3, `MaterialExpressiveTheme`, `MotionScheme`, the FAB menu, and button groups are still internal APIs, so they are built to the spec in-house: `ui/theme/Motion.kt`, `ui/components/Segmented.kt` (segmented lists, `ConnectedChoice` connected single choice), and `ui/main/FabMenu.kt`. The corner radius scale is in `KakeyShapes`; the warning orange and success green are in `ExtendedColors`; every other color comes from `MaterialTheme.colorScheme`.
- Per-second refresh: `rememberNow()` ticks on whole seconds, and codes and rings recompose with it.

## Tests

- `make test-android`: localization guard → ktlint → detekt → Lint → JVM unit tests. The unit tests call the host build of the core through JNA. `ManualDispatcher` in `Fakes` cancels the caller after a file operation is queued, `MemoryDavExecutor` drives the cloud storage backends, and MockWebServer verifies `OkHttpExecutor`.
- `make test-android-device`: `MainFlowTest` in `src/androidTest` drives the real app through the Compose semantics tree: create a vault → add an account manually → the code matches the core's → copy (with `EXTRA_IS_SENSITIVE`) → lock → wrong password → unlock → reset. It isn't part of `make test` or CI. Reports are in `Build/Android/Gradle/app/reports/androidTests/connected/`.
  - **Sandbox exception**: instrumented tests touch the app's own sandbox on the device (`files/Kakey/`, DataStore, Keystore). This is the only exception to "tests never touch real storage", and it is used only for UI flows. Before and after each test, the app's own reset path (`VaultStore.resetApplication`, see `AppSandbox`) wipes it. `pm clear` isn't used because it also kills the test process. Gradle uninstalls the app when the run ends.
  - The tests clear `autofill_service` for the run and restore it afterward: a password manager's "save password" prompt takes focus, and the app then can't read the clipboard.
  - The owner verification before reset is a system window that Compose can't see. The test detects `BiometricPrompt` / `ConfirmDeviceCredential` with `dumpsys window windows`, presses Back to cancel when needed, and then takes the same reset path.
  - Dependencies are pinned in the version catalog: AndroidX Test runner and rules 1.7.0, ext junit 1.3.0, espresso-core 3.7.0 (the 3.5.0 pulled in by `ui-test` reflectively calls `InputManager.getInstance`, which Android 17 removed). `testOptions.animationsDisabled = true`.
- Screenshots: `make android-screenshots` captures every screen from the demo vault × light and dark appearance × three languages into `Build/Screenshots/android/`.

## Platform Pitfalls

- With `FLAG_SECURE`, `screencap` returns a black image for the home screen and the detail sheet (its window inherits the flag), so screenshot checks only work with the Debug demo vault.
- On an emulator, the first input into a text field makes Gboard show a stylus handwriting intro that swallows the input. `scripts/screenshots.sh` turns it off with `settings put secure stylus_handwriting_enabled 0`.
- The per-second countdown keeps the UI from ever going idle, so `uiautomator dump` often can't get the hierarchy. UI automation taps by screenshot coordinates.
- With a password manager on the device, the system shows a "save password" panel after creating a vault. Turn it off before driving the app manually with adb.
